# Agent Notes for This Blog

This repository is a custom static blog, not Hexo/Jekyll. Treat `scripts/build-site.js` as the site generator, `content/posts/*.md` as source posts, and `_site/` as generated output.

## Safety and Privacy

- Do not add local absolute paths, machine usernames, shell history, credentials, tokens, or private notes to tracked files.
- If importing a draft from outside the repo, copy only the article content and normalize paths before committing.
- Do not commit or push unless the user explicitly asks for it.
- Keep commits scoped. If unrelated local changes exist, leave them alone and stage only the files required for the requested change.

## New Post Workflow

1. Copy the draft into `content/posts/<slug>.md`.
2. Add front matter:

```yaml
---
title: "Post Title"
date: "YYYY-MM-DD"
slug: "post-slug"
categories:
  - Category
tags:
  - tag-one
  - tag-two
---
```

3. Keep tags limited and meaningful. Usually 2-4 tags is enough.
4. Use the current date for newly added posts unless the user specifies another date.
5. Keep the visible `# Title` matching the front matter title.
6. The opening slogan/tagline should be italic, not a blockquote:

```markdown
*Short slogan here.*
```

7. If the draft contains images or GIFs, copy them into the repo under `assets/` and update Markdown links to repo-relative public paths. Avoid hotlinking unless there is a deliberate reason.
8. If the draft contains LaTeX math, `$...$`, `$$...$$`, `\(...\)`, and `\[...\]` are supported through KaTeX.

## Style Conventions

- Keep article titles readable on cards. If a title is very long, prefer improving CSS only if multiple pages are affected.
- Preserve the blog's current visual direction: Chirpy-like layout, pale cyan/blue palette, sidebar navigation, Live2D, click fireworks, day/night toggle, and spinner intro.
- Related posts, reading time, archive, categories, tags, search, heading anchors, 404, and back-to-top are generated by `scripts/build-site.js`.
- For Plonky3-style series posts, use:

```yaml
series: "Plonky3"
seriesPart: 1
```

The generator will render the series navigation when at least two posts share the same `series`.

## Build and Local Preview

- Build:

```bash
npm run build
```

- Serve locally:

```bash
npm run server
```

- Local preview URL pattern:

```text
http://127.0.0.1:4000/posts/<slug>/
```

- `_site/` is generated and ignored. Do not manually edit files in `_site/`.
- If the local server cannot bind to port `4000`, check for an existing `scripts/serve-static.js` process before starting another one.

## Deployment Workflow

When the user asks to publish:

1. Run `npm run build`.
2. Inspect `git status -sb` and `git diff --stat`.
3. Stage only relevant source files.
4. Commit with a concise message.
5. Push `main`:

```bash
git push origin main
```

6. GitHub Pages deploys via `.github/workflows/pages.yml` on push to `main`.
7. If needed, trigger or inspect the workflow with `gh`:

```bash
gh workflow run "Deploy blog to Pages" --ref main
gh run list --workflow "Deploy blog to Pages" --limit 5
gh run watch <run-id> --exit-status
```

## Common Checks

- Verify the generated article exists:

```bash
test -f _site/posts/<slug>/index.html
```

- Confirm the post is indexed on home/posts/search:

```bash
rg "<slug>|Post Title" _site/index.html _site/posts/index.html _site/search.json
```

- For TOC or heading-anchor bugs, inspect slug generation in `scripts/build-site.js`.
- For bottom-of-page visual clipping, adjust layout spacing in `assets/css/chirpy-like.css`, not generated HTML.
